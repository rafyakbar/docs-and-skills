# Step 1: Configuration

## Purpose

Define all tunable parameters at the top of the notebook so the user can see and adjust them easily. This follows the jupyter-notebook-development convention of separating configuration from program logic.

## Variables Explained

### Identity & URLs

```python
NAME = "livewire-v4"
BASE_URL = "https://livewire.laravel.com"
START_URL = "https://livewire.laravel.com/docs/4.x/quickstart"
```

- **`NAME`**: Used to name the output directory. Format: `<topic>-v<version>`. The topic is lowercase kebab-case. Use the project name (e.g., `filament-v5`, `alpinejs-v3`, `fluxui-v2`).
- **`BASE_URL`**: The root domain of the documentation site. Used with `urljoin()` in Step 3 to convert relative paths to absolute URLs.
- **`START_URL`**: The first page to fetch. This should be a documentation page that has the full sidebar menu visible. Usually the "Overview" or "Introduction" page of the docs section.

### Directory Structure

```python
BASE_DIR = f"docs/{NAME.replace('-', '_')}"
HTML_DIR = f"{BASE_DIR}/html"
REFERENCES_DIR = f"{BASE_DIR}/references"
REFERENCES_JSON = os.path.join(BASE_DIR, "references.json")
```

Follows the convention: `docs/<topic>_v<version>/`:

```text
docs/filament_v5/
├── references.json        ← Link metadata (generated by Step 3)
├── references.md          ← Index file (generated by Step 6, refined by AI)
├── references/            ← Individual Markdown files
│   ├── 001_<subject>.md
│   └── ...
└── html/                  ← Raw HTML downloads (temporary)
    ├── 001_<subject>.html
    └── ...
```

- `BASE_DIR`: The parent directory for all output.
- `HTML_DIR`: Temporary storage for raw HTML before conversion.
- `REFERENCES_DIR`: Final Markdown output, one file per page.
- `REFERENCES_JSON`: Shared metadata file that connects Steps 3-6. This replaces cross-cell variable dependencies.

### Request Throttling

```python
DELAY_RANGE = (0.2, 0.6)
```

A random delay between 0.2 and 0.6 seconds is applied after each request. This prevents overwhelming the server and getting rate-limited or blocked. The randomness avoids predictable patterns that anti-bot systems detect.

### Caching

```python
MAX_AGE_DAYS = 7
MAX_AGE_SECONDS = MAX_AGE_DAYS * 86400
```

On subsequent runs, files younger than `MAX_AGE_DAYS` are not re-downloaded. This saves bandwidth and time when re-running the notebook. Use `time.time() - os.path.getmtime()` (not `date.today()`) so the comparison works with file modification timestamps directly.

### HTTP Headers

```python
HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
}
```

Some sites block requests without a browser-like User-Agent. This header mimics a real Chrome browser on Windows. If a site is still blocking requests, you may need to add additional headers like `Accept`, `Accept-Language`, or `Referer`.

### CSS Selectors

```python
SIDEBAR_SELECTOR = "div#navigation-items"
CONTENT_SELECTOR = "div#content-area"
```

These are the most important variables. They must be discovered during **Manual Site Inspection** before writing the notebook. Every documentation site uses different HTML structure.

- `SIDEBAR_SELECTOR`: A CSS selector that uniquely identifies the sidebar navigation container. Used with `soup.select_one()`.
- `CONTENT_SELECTOR`: A CSS selector that uniquely identifies the main content area. Used in Step 5 to isolate the documentation text.

### Debug Output

```python
print("Configuration:")
print(f"  NAME              : {NAME}")
...
```

Printing all variables lets the user verify the configuration at a glance before running anything. This is a jupyter-notebook-development requirement.

### Directory Creation

```python
os.makedirs(HTML_DIR, exist_ok=True)
os.makedirs(REFERENCES_DIR, exist_ok=True)
```

`exist_ok=True` prevents errors if the directories already exist from a previous run.

## Why This Matters

Having all configuration in one cell makes the notebook:
- **Reproducible**: Change `START_URL` to crawl a different starting page
- **Reusable**: Adapt for a different documentation site by changing `SIDEBAR_SELECTOR` and `CONTENT_SELECTOR`
- **Transparent**: User sees exactly what's being configured
- **Independent**: Each subsequent cell computes its own paths from these shared constants
